What this experiment establishes

The portable Pi browser tests use the published library, real IndexedDB and a scripted provider. They exercise graceful reopen, abrupt interruption, ownership locks and unsafe tool recovery. Those Pi tests use no real model, account or production task. Separate Office trials use only newly created test documents.

The Windows Pi trial then performed a real native screen observation and one scratch-file effect. After the host closed before the tool returned, a fresh host recovered the exact interrupted run without repeating that effect. Both runs exited zero with empty error lists. This trial uses a trusted page; the Windows worker relay and production journal migration remain separate work. Its earlier recorder failure and the verified correction are preserved in the evidence.

The compiled C++ host, loader and browser assets total 1,611,847 bytes. Defender blocked that executable before a host process existed. The separate accepted Python host successfully ran the real canvas and Pi in WebView2; that success does not validate the blocked binary or predict a complete replacement's size.

The native canvas proof uses Python 3.15.1, WebView2 155.0.4283.62 and the official loader, without Qt, Tk or CLR imports. Its 13 checks cover interaction and geometry at 125% scaling. Removing Python and the remaining production Qt screens is still implementation work.

WebView2 is still a browser engine. Sharing Windows' installed runtime avoids bundling another engine; renderer memory and the cost of Office or other web apps still exist. Browser workers also need native lifetime and wake policies for background work. Comparable memory and CPU measurements have not been made.

Open design question: how little UI can a document card show?

The requested default is the document, a small title and essential controls. The document-mode prototype hides Toolkit's navigation/footer and reclaims the space in its geometry checks. Formatting, file and editor controls should remain available on demand through supported app layouts. The production assets retain their current presentation.

Several cards share one app profile and sign-in; each still loads the editor needed for its document. A stable document destination must survive authentication redirects. New-document windows should become saved cards, while authentication popups retain their opener relationship. Those ownership changes are not yet implemented.

Word and Excel offered Show tabs only; it was invoked in both, with Excel's checked state verified. The real VS Code web workbench and its native file picker opened, but the automation helper could not operate the picker's filename/Open controls. No local-file edit/save/reopen result is claimed. Browser-only VS Code also needs a local or remote backend for OS terminals and runtime-dependent extensions. Read the supported options and remaining questions.
