How should the toolbar change?

The same scenario drives three arrangements. Each row measures how far the menu and inbox buttons move from where they sat at idle, because persistent controls that move under the pointer break spatial memory. Switch between floating and attached edges in the demo controls.

Recommendation: the island, floating, with an edge-to-edge hit target

Morph for moments, detach for durations. Dictation, transcription and a new question are short and hold your attention, so they take over the centre shape, as the Dynamic Island does for its single activity. Agent work, meeting recording and the keyboard layer last minutes and run independently, so each gets its own detached minimal pill. Apple uses the same split when several Live Activities run at once.

Keep information, reveal controls. A minimal pill shows live state (a spinner, the recording timer, NAV), and hovering reveals its Stop button. Questions expand the island downward for a few seconds, then settle into the orange "Needs you" pill. Clicking that pill expands the question again.

Float, but keep the edge target. Liquid Glass bars float inset and concentric. Apple replaced the edge-attached notch with the floating island. Workspace still owns the strip above the glass, so a cursor thrown against the top edge lands on the nearest control. That keeps the Fitts's-law benefit of attachment.

Measured over this scenario. At the widest point, the menu moves 183 px in the single capsule, because every activity widens the one shape. It moves 233 px with glass groups (254 px attached), because the ambient readout never yields its space. In the island it moves 0 px for dictation, transcription, agent work, recording and the keyboard layer. It moves 24 px for the settled "Needs you" pill and 91 px for the five seconds the question is expanded. The island holds a minimum width equal to its idle readout, which is what makes moments free.
